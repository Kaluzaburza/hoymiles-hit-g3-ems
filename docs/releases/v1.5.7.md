> This patch is published only after the exact tagged commit passes the full
> offline release gate, exact-final deployment and live acceptance on installation_1
> and `installation_2`, and the required GitHub workflow including Hassfest,
> HACS validation and the conditional firmware compile job. The offline gate

## User update steps / Kroki po aktualizacji

1. **HACS:** keep RCEm in shadow mode and disable every automatic or scheduled
   EMS writer. Update **EMS for Hoymiles HIT-(5–20)L-G3** to **v1.5.7**.
   **PL:** pozostaw RCEm w trybie shadow i wyłącz wszystkie automatyczne oraz
   harmonogramowe zapisy EMS. Zaktualizuj w HACS integrację
   **EMS for Hoymiles HIT-(5–20)L-G3** do **v1.5.7**.
2. **Home Assistant:** restart after HACS installs the update. The first start
   loads the new Python runtime and copies managed EMS package **1.5.7**;
   validate the configuration and perform the second restart requested by the
   managed-package Repair. Keep all writers disabled during both restarts.
   **PL:** uruchom Home Assistant ponownie po instalacji aktualizacji z HACS.
   Pierwszy start ładuje nowy runtime Python i kopiuje zarządzany pakiet EMS
   **1.5.7**; sprawdź konfigurację i wykonaj drugi restart wymagany przez
   komunikat Napraw pakietu. Podczas obu restartów pozostaw wszystkie zapisy
   wyłączone.
3. **ESP32 / ESPHome:** no firmware rebuild or upload is required. Firmware
   from the last compatible immutable tag **v1.5.6** remains valid; HACS does
   not flash the ESP32.
   **PL:** ponowna kompilacja ani wgrywanie firmware nie są wymagane. Firmware
   z ostatniego zgodnego, niezmiennego tagu **v1.5.6** pozostaje właściwe;
   HACS nie wgrywa ESP32.
4. **Verification / Weryfikacja:** confirm package **1.5.7 / Ready**, exactly
   **294** localized entities, no unexpected owner, physical mode or Modbus
   write, and no repeated RCE full-plan recalculation for an unchanged
   completed GCF cohort. Where fresh physical GCF readback proves enabled zero
   export, confirm `fixed_zero_export` and factor **0.80**.
   **PL:** potwierdź pakiet **1.5.7 / Gotowe**, dokładnie **294** lokalizowane
   encje, brak nieoczekiwanego właściciela, zmiany fizycznego trybu lub zapisu
   Modbus oraz brak powtarzanego pełnego przeliczania planu RCE dla niezmienionej
   kompletnej kohorty GCF. Gdy świeży fizyczny odczyt GCF potwierdza włączony
   zerowy eksport, sprawdź `fixed_zero_export` i współczynnik **0,80**.

## Hotfix scope / Zakres hotfixu

- Fixes repeated RCE plan recalculation caused by multi-part delivery of one
  physical GCF report.
- Retains only the last coherent cohort for a bounded maximum of five seconds
  while that same report finishes. The mixed intermediate state does not
  immediately replace the coherent cohort.
- Consumes one genuinely changed completed semantic cohort at most once and
  avoids recalculating an identical completed cohort.
- Remains fail-closed when GCF incoherence persists beyond the grace period.
  Missing, stale, future, malformed and unsupported physical readback remains
  untrusted.
- Preserves exact fixed-zero-export behavior: fresh coherent enabled GCF plus
  `0.0%` physical limit selects `fixed_zero_export`, excludes restricted live
  and historical learning, and uses **0.80 × Solcast**.
- Does not change RCE economic optimization, slot selection, revenue, wear
  cost, reserve, requested power or execution eligibility. The optimizer
  remains heuristic and this release makes no global-optimum claim.
- Does not change the scheduler, full-block writer, FC16/FC03 semantics,
  Modbus maps, firmware, tariff, RCEm, Aurora/dashboard/frontend or parallel
  communication behavior. It does not add RCE market charging and does not
  include EMS Supervisor.
- Master FC03 remains acknowledgement of Master configuration only. No
  per-Slave protocol acknowledgement is claimed.

- Naprawia powtarzane przeliczanie planu RCE wywołane częściowym dostarczaniem
  jednego fizycznego raportu GCF.
- Zachowuje ostatnią spójną kohortę tylko przez ograniczone maksimum pięciu
  sekund, gdy kończy się ten sam raport. Mieszany stan pośredni nie zastępuje
  natychmiast spójnej kohorty.
- Używa rzeczywiście zmienionej kompletnej kohorty semantycznej najwyżej raz i
  nie przelicza ponownie identycznej kompletnej kohorty.
- Po przekroczeniu czasu łaski trwała niespójność pozostaje fail-closed. Dane
  brakujące, nieświeże, przyszłe, wadliwe lub nieobsługiwane są niezaufane.
- Zachowuje dokładną semantykę zerowego eksportu: świeży spójny odczyt,
  włączony GCF i fizyczny limit `0,0%` wybierają `fixed_zero_export`, wykluczają
  uczenie z okresu ograniczenia i stosują **0,80 × Solcast**.
- Nie zmienia ekonomii RCE, wyboru slotów, przychodu, kosztu zużycia, rezerwy,
  żądanej mocy ani kwalifikacji wykonania. Optymalizator pozostaje heurystyczny;
  wydanie nie dowodzi globalnego optimum.
- Nie zmienia schedulera, pełnego zapisu bloku, FC16/FC03, map Modbus, firmware,
  taryfy, RCEm, Aurora/dashboard/frontend ani komunikacji równoległej. Nie
  dodaje ładowania z rynku RCE i nie zawiera EMS Supervisora.
- FC03 Mastera nadal potwierdza wyłącznie konfigurację Mastera. Wydanie nie
  deklaruje protokołowego ACK każdego Slave'a.
